# Skill design

- Give each skill one distinct trigger and one useful outcome. Extend an existing skill when the decision path is the same.
- Put only rules needed for the current task in `SKILL.md`; keep examples and long checklists in optional references.
- Require focused evidence for behavior changes. Pause only for high-risk operations or unresolved external facts.
- State Rails-specific rules here; link to Ruby foundation skills for language-level guidance rather than copying it.
- Use a blocking instruction only when bypassing it can cause concrete harm. Avoid generic preambles, repeated contracts, and mandatory section templates.
- Keep examples only when they disambiguate a real edge case or provide a useful copyable pattern.
